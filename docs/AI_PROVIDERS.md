# ИИ-провайдеры анализа

Документ описывает, как подключить бесплатные языковые модели OpenRouter
(и другие провайдеры), сохранив работу приложения без внешних сервисов.

---

## 1. Разделение ответственности

| Что делает | Чем |
|---|---|
| Числовые расхождения, нормализация единиц измерения | детерминированные правила |
| Даты документов, срок действия, область применения, совпадение моделей | детерминированные правила |
| Тип сигнала, его серьёзность, статус оценки | детерминированные правила |
| Дополнительные формулировки утверждений | модель (необязательно) |
| Уточнение типа утверждения | модель (необязательно) |
| Пояснение к находке | модель (необязательно) |

Модель **не может** объявить факт доказанным:

* находка, предложенная моделью, принимается только если модель процитировала
  фрагмент, который дословно есть в одном из источников; тип такой находки
  принудительно меняется на `needs_human_review`;
* утверждение, извлечённое моделью, сохраняется только с дословным фрагментом
  источника и помечается как требующее подтверждения пользователем;
* пояснение модели выводится отдельным блоком и не меняет тип, серьёзность
  и ограничения находки.

Если внешний провайдер недоступен, приложение явно сообщает об этом
(в сводке запуска и в ограничениях анализа) и продолжает работу на
локальной эвристике. Ложные находки при этом не создаются.

---

## 2. Провайдеры

| `LLM_PROVIDER` | Что это | Ключ | Данные уходят наружу |
|---|---|---|---|
| `mock` | локальная эвристика, без сети (по умолчанию) | нет | нет |
| `openrouter` | бесплатные модели OpenRouter | `OPENROUTER_API_KEY` | да |
| `ollama` | локальные модели с открытыми весами | нет | нет (на этом же компьютере) |
| `openai_compatible` | любой OpenAI-совместимый API | `LLM_API_KEY` | да |

---

## 3. OpenRouter: пошаговая настройка

### Шаг 1. Получите ключ

1. Откройте <https://openrouter.ai/keys> и войдите в аккаунт (GitHub, Google
   или почта).
2. Нажмите **Create Key**, задайте понятное имя (например,
   `obeshchanie-local`) и скопируйте ключ.
3. Ключ выглядит как `sk-or-v1-...`. **Не отправляйте его в чат и не
   коммитьте.**

Бесплатный тариф OpenRouter помечает модели суффиксом `:free` — у них есть
общая бесплатная очередь с ограничением по частоте запросов.

### Шаг 2. Проверьте, какие модели бесплатны сейчас

Список бесплатных моделей меняется. Актуальный список берётся из
официального каталога OpenRouter (`GET /api/v1/models`, ключ не нужен):

```powershell
.\.venv\Scripts\python.exe scripts\check_openrouter_models.py --all
```

Пример вывода (данные на 21.10.2026):

```
Моделей всего: 468
  с нулевой ценой: 20 · в бесплатной очереди (:free): 17

Бесплатные модели сейчас (нулевая цена):
  - minimax/minimax-m3.1-flash:free [:free] (контекст 1000000)
  ...
```

Проверить конкретную модель:

```powershell
.\.venv\Scripts\python.exe scripts\check_openrouter_models.py --model minimax/minimax-m3.1-flash:free
```

Скрипт покажет, существует ли модель, в какой она очереди и поддерживает ли
структурированный ответ.

### Шаг 3. Задайте переменные окружения

Откройте `.env` в корне проекта (файл не коммитится) и добавьте:

```env
LLM_PROVIDER=openrouter
OPENROUTER_API_KEY=sk-or-v1-ваш-ключ
OPENROUTER_MODEL=minimax/minimax-m3.1-flash:free
```

Идентификатор модели берётся из шага 2. В коде он не зашит: смена модели —
это правка одной переменной.

Дополнительно (необязательно):

```env
# Резервные модели: используются только при 429 и только из этого списка
OPENROUTER_FALLBACK_MODELS=другая/модель:free,третья/модель:free
# Заголовки атрибуции, которые OpenRouter рекомендует указывать
OPENROUTER_HTTP_REFERER=http://localhost:5173
```

### Шаг 4. Перезапустите backend

```powershell
# нативный режим
powershell -ExecutionPolicy Bypass -File scripts\run-backend.ps1

# контейнерный режим: переменные подхватываются при пересоздании контейнера
podman compose up -d --build
```

### Шаг 5. Проверьте один запрос

```powershell
# состояние провайдера (ключ не выводится)
curl.exe http://127.0.0.1:8000/api/v1/settings/ai -H "Authorization: Bearer <ваш токен>"
```

Быстрая проверка без токена — сравнение классификации на фиксированном наборе:

```powershell
.\.venv\Scripts\python.exe scripts\compare_providers.py
```

Вывод показывает совпадение типов для локальной эвристики и для внешней
модели на одном и том же наборе из 20 утверждений. Формат вывода:

```
=== mock (mock-rules-1) ===
совпадение типа: 70.0% · статус оценки: 20.0% · ответов: 20/20

=== openrouter (<идентификатор вашей модели>) ===
совпадение типа: <фактическое значение> · статус оценки: <фактическое значение> · ответов: 20/20

=== разница ===
openrouter против mock: <разница> по совпадению типа
```

Числа для внешней модели зависят от выбранной модели, версии набора и
доступности сервиса в момент запуска: воспроизводимые утверждения здесь
не приводятся. Базовое значение локальной эвристики (70 % по типу на
версии набора 2024.1) защищено тестом
`app/backend/tests/test_provider_benchmark.py` — падение ниже порога означает
регрессию правил.

Набор лежит в `app/backend/app/benchmarks/claim_benchmark.json` и не меняется
между провайдерами, поэтому числа сопоставимы.

## 4. Как вернуться к mock-режиму

В `.env` укажите:

```env
LLM_PROVIDER=mock
```

Перезапустите backend. Ключ можно оставить в файле: при `LLM_PROVIDER=mock`
он не используется и никуда не передаётся. Чтобы убрать его совсем —
удалите строку `OPENROUTER_API_KEY=...` из `.env`.

## 5. Что происходит при ошибках

| Ситуация | Поведение |
|---|---|
| Нет ключа или модели | провайдер не активен, работает локальная эвристика |
| 429 — лимит бесплатной очереди | повтор с паузой (до `OPENROUTER_MAX_RETRIES`), затем резервная модель из `OPENROUTER_FALLBACK_MODELS`; платная модель не подставляется |
| 401/403 — ключ отклонён | повторов нет, в логах только код ответа, ключ не пишется |
| 404 — модель не найдена | понятное сообщение с просьбой проверить идентификатор |
| 400 — запрос отклонён | повторов нет; если причина в `response_format`, запрос уходит без него |
| 5xx — ошибка сервиса | ограниченные повторы с паузой |
| Нет связи / таймаут | повторы не повторяют сетевую ошибку дольше лимита, анализ продолжается без модели |
| Ответ не является JSON или не соответствует схеме | ответ отбрасывается, в сводке фиксируется, что модель не дала результата |

Ключ API не попадает ни в логи, ни в ответы API, ни в отчёты: он хранится в
`SecretStr`, в журнал пишутся только класс ошибки и код ответа. Это
проверяется тестами `app/backend/tests/test_secret_hygiene.py`.

## 6. Ограничения бесплатного тарифа

* Общая очередь OpenRouter: при большом числе пользователей ответ может
  ждать или возвращать 429. Поэтому в конфигурации есть резервный список
  моделей и ограниченные повторы.
* Бесплатные модели меняются: идентификатор, который работал вчера, может
  исчезнуть из каталога. Проверяйте модель скриптом
  `scripts/check_openrouter_models.py`.
* Один анализ товара — это несколько запросов к модели (извлечение
  утверждений, классификация, пояснения). При большом числе товаров очередь
  исчерпается быстрее.
* Данные загруженных документов уходят во внешний сервис. В режиме `mock`
  или `ollama` они остаются на компьютере.
