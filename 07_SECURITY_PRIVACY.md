# Безопасность и приватность

## Основные риски

-   пользователь получает доступ к чужим товарам/файлам;
-   вредоносные или чрезмерно большие загружаемые файлы;
-   утечка API-ключей LLM;
-   prompt injection внутри загруженных документов и отзывов;
-   SQL injection / XSS;
-   утечка персональных данных из отзывов;
-   отчёт выдаёт неподтверждённый вывод как установленный факт.

## Требования

1.  Все сущности привязаны к workspace; backend проверяет права на
    каждой операции.
2.  Не хранить секреты в Git. Создать `.env.example` с placeholders.
3.  Ограничить размер файла, разрешённые форматы и количество загрузок.
4.  Хранить файлы под случайными server-generated именами.
5.  Не исполнять загруженные файлы и не доверять MIME type, указанному
    клиентом.
6.  Парсеры запускать с ограничениями по времени/ресурсам, где это
    возможно.
7.  Удалять/маскировать секреты из логов.
8.  Текст документов считать недоверенными данными, а не инструкциями
    для LLM.
9.  Не позволять загруженному тексту менять system prompt или вызывать
    инструменты.
10. LLM не получает доступ к shell, базе напрямую или произвольным URL.
11. Экранировать пользовательский текст в HTML-отчётах.
12. Не хранить больше личных данных, чем нужно для сценария.
13. Предупреждать пользователя, если внешний LLM-провайдер может
    получать загруженный текст.
14. Предоставить удаление товара и связанных файлов/источников.
15. Добавить тесты на попытки доступа к чужому workspace.

## Юридические границы

Продукт не выносит юридическое заключение, не подтверждает сертификаты у
государственного реестра автоматически и не объявляет продавца
нарушителем. Все такие случаи маркируются как требующие человеческой
проверки.
